# Avito SVO — сбор телефонов рекрутёров с Авито

Автоматический сбор объявлений по запросу **«сво по контракту»**
(Москва и МО): обход выдачи, телефоны рекрутёров, база SQLite,
раз в день — эксель-отчёт в Telegram.

- Бот: **@avitosobiralkabot** (кнопки: эксель / спарсить / остановить)
- Тихий режим: сбор 07:00–11:00 без сообщений, отчёт в 12:00 МСК
- Каталог на сервере: `/root/avito-svo`

## Архитектура — четыре сервиса

```
avito-svo-browser   ff_browser_daemon.js        резидентный Firefox:
                                                вкладка Авито открыта
                                                постоянно, ws-порт 9334

avito-svo-bot       tg_bot.py                   TG-бот + расписание,
                                                запускает сбор subprocess'ом

avito-ff-monitor    firefox_session_monitor.py  экспорт сессии из
                                                ручного Firefox

cron /etc/cron.d/oom-priority + oom_priority.sh защита сбора от OOM-killer
```

Сбор — это `ff_collect.py`: бот (или api_helper) запускает его как
отдельный процесс, коллектор подключается к резидентному браузеру
по websocket и работает в собственном контексте, закрывая только
свои вкладки.

## Как работает логика сбора

### 1. Сессия (вход на Авито)

Логин выполняется **руками** в реальном Firefox на сервере (профиль
`/root/.mozilla/firefox/ai-agent`, экран виден через noVNC `:6080`).
`firefox_session_monitor.py` каждые 15 секунд снимает копию
`cookies.sqlite` профиля и, увидев куки залогиненного пользователя,
экспортирует сессию в `avito_session.json`. Демон резидентного
браузера подхватывает файл (в том числе при изменении) и заливает
куки во вкладку — без перезапуска чего-либо.

### 2. Резидентный браузер

`ff_browser_daemon.js` (Node, `firefox.launchServer`, порт 9334,
прокси `socks5://127.0.0.1:10808` — выход в Москве) держит Firefox
с вкладкой поиска «сво по контракту» ПОСТОЯННО. Постоянно открытая
вкладка вместо «новый Firefox на каждый прогон» — меньше блокировок
«Доступ ограничен» и капч.

- ws-эндпоинт → файл `browser.ws`, пульс каждые 45 с → `browser.heartbeat`
- лёгкий скролл ~5 мин, мягкий reload ~20 мин (когда сбора нет)
- попапы «Хорошо/Понятно/Принять» закрываются сам
- пересоздание контекста ежедневно ~04:30 МСК (гигиена памяти)
- если демон умер — ff_collect автоматически уходит в фолбэк:
  собственный persistent-профиль `ff_profile/`

### 3. Прогон ff_collect.py (`--mode search`)

1. `flock .parser.lock` — два прогона одновременно невозможны
   (второй молча выходит с rc=2).
2. Подключение к резидентному браузеру (heartbeat свежее 180 с);
   поиск «сво по контракту» → сортировка «По дате».
3. **Обход строго по порядку.** DOM у Авито виртуализированный:
   при прокрутке карточки перемонтируются не по порядку, поэтому
   каждый круг собирает смонтированные карточки с их вертикальными
   координатами, сортирует по Y и обрабатывает непросмотренные
   сверху вниз; после порции — прокрутка 700–1100 px.
4. **Дедуп.** Нормализованный заголовок уже встречался (в этом
   прогоне или в базе с номером) → карточка пропускается целиком,
   без ховера (клон, статус `dup_title`). Круг без живых карточек —
   быстрая прокрутка крупным шагом.
5. **Телефон без захода в объявление.** Hover по карточке → кнопка
   «Показать телефон» → клик → номер приходит **картинкой**
   (OCR tesseract; md5-кэш: у клонов одного рекрутёра картинка
   байт-в-байт одинаковая) или текстом. Нормализация `+7XXXXXXXXXX`.
   Нет кнопки телефона → `no_phone`, в следующие прогоны карточка
   не тыкается.
6. **БД пишется по ходу.** Каждый номер — сразу после находки;
   клоны/без-телефона — пачками по 25. Авария или «Остановить»
   ничего не теряют.
7. **Блоки.** «Доступ ограничен» снимается нажатиями «Продолжить»
   и F5; капча не решается — жёсткий cooldown 20 минут. SIGTERM —
   мягкая остановка (доканчивает карточку, сохраняет всё).
8. **Повторы пропускаются.** `done_ids` — все просмотренные id
   (с телефоном, no_phone, dup_title, error) молча скипаются,
   поэтому регулярные прогоны короткие и добирают только новое.

### 4. Отчёт excel_report.py

Только строки с телефоном. Колонки: **Название · Телефон · Ссылка ·
Источник · Одинаковых вакансий · Описание** (последняя — широкая,
текст сниппета карточки). «Одинаковых вакансий» — сколько в базе
объявлений с тем же текстом (клоны-спам одного рекрутера).
Каждый день — отдельный лист («19.09», «18.09»…), свежий сверху.
В 12:00 МСК бот присылает файл в чат (ретраи каждую минуту
до 12:59, максимум 10 попыток).

## Расписание (МСК)

| время | что происходит |
|---|---|
| 07:00, 08:00, 09:00, 10:00, 11:00 | тихий плановый сбор: поиск «сво по контракту», макс 300 номеров, бюджет 30 мин |
| 12:00 | эксель-отчёт в чат |
| ~04:30 | демон пересоздаёт контекст браузера |

Перед каждым плановым прогоном бот проверяет свободную память;
при нехватке (~2 ГБ) прибирает посторонний браузер (его сторож
пересоздаёт сам). Каждую минуту cron `oom-priority` расставляет
`oom_score_adj`: процессы сбора → −200, посторонний Firefox → +500.

## Управление

**Кнопки бота:** 📊 эксель · 🔍 спарсить «сво по контракту» (полный
прогон + эксель) · ⏹ остановить. Команды: `/поиск /search`,
`/стоп /stop`, `/эксель /excel`, `/start`. Чужие чаты молча
игнорируются (`ALLOWED_CHATS`).

**С сервера (SSH):**

```bash
python3 /root/avito-svo/api_helper.py status        # сбор идёт? база? лог?
python3 /root/avito-svo/api_helper.py collect       # запуск: поиск, макс 300
python3 /root/avito-svo/api_helper.py collect search 100
python3 /root/avito-svo/api_helper.py stop          # мягкая остановка
python3 /root/avito-svo/api_helper.py report        # эксель → base64
```

**systemd / журналы:**

```bash
systemctl status avito-svo-bot avito-svo-browser avito-ff-monitor
journalctl -u avito-svo-bot -f           # лог бота
tail -f /root/avito-svo/ff_collect.log   # живой лог коллектора
tail -f /root/avito-svo/browser_daemon.log
```

|---|---|
| `ff_browser_daemon.js` | резидентный браузер (вкладка Авито всегда открыта) |

`shots_ff/` (скриншоты), `*.log`, `bot_state.json`, `browser.ws`,
`browser.heartbeat`.

## Зависимости сервера

Python 3.12 + playwright (Firefox), tesseract-ocr (+ русский),
openpyxl, requests; Node — пакет драйвера playwright
(`/usr/local/lib/python3.12/dist-packages/playwright/driver/package`).
Прокси `socks5://127.0.0.1:10808` (выход в Москве), X-дисплей `:1`
(noVNC `:6080`), TZ Europe/Moscow.

## Настройка (переменные окружения)

| переменная | по умолчанию | действие |
|---|---|---|
| `AVITO_ALLOWED_CHATS` | id владельца | кому бот раздаёт базу |
| `AVITO_MAX_PHONES` | 5 (юнит: 20) | лимит телефонов из карточек за сессию |
| `AVITO_COMPANY_COL` | выкл | `1` — добавить колонку «Вакансий компании» |
| `AVITO_PROXY` | `socks5://127.0.0.1:10808` | прокси браузера |
| `AVITO_BASE_DIR` | `/root/avito-svo` | базовый каталог |

## Запуск сбора вручную

```bash
DISPLAY=:1 AVITO_PROXY=socks5://127.0.0.1:10808 \
    python3 /root/avito-svo/ff_collect.py \
    --mode search --max-phones 0 --time-budget 1500
```

Аргументы: `--mode search|category` (search — основной), `--query`
(текст запроса), `--max-phones 0` (0 = без лимита), `--max-cards`,
`--max-pages` (0 = вся пагинация), `--time-budget` (сек).
