# Avito SVO

Сбор телефонов рекрутёров с Авито. Поиск по запросу «сво по контракту» (Москва и МО). Обход выдачи, телефоны, база SQLite. Раз в день эксель-отчёт в Telegram.

- Бот: @avitosobiralkabot (кнопки: эксель / спарсить / остановить)
- Тихий режим: сбор с 07:00 до 11:00, без сообщений. Отчёт в 12:00 МСК
- Каталог на сервере: `/root/avito-svo`

## Состав (4 сервиса)

```
avito-svo-browser    ff_browser_daemon.js         резидентный Firefox: вкладка Авито
                                                  открыта постоянно, ws-порт 9334
avito-svo-bot        tg_bot.py                    TG-бот и расписание. Запускает
                                                  сбор отдельным процессом
avito-ff-monitor     firefox_session_monitor.py   экспорт сессии из ручного Firefox
cron                 /etc/cron.d/oom-priority     защита сбора от OOM-killer
```

Сбор делает `ff_collect.py`. Бот (или api_helper) запускает его как отдельный процесс. Коллектор подключается к резидентному браузеру по websocket. Работает в собственном контексте и закрывает только свои вкладки.

## Как работает сбор

### 1. Сессия (вход на Авито)

Логин выполняется руками в реальном Firefox на сервере. Профиль `/root/.mozilla/firefox/ai-agent`. Экран виден через noVNC (порт 6080).

`firefox_session_monitor.py` каждые 15 секунд снимает копию `cookies.sqlite` этого профиля. Увидел куки залогиненного пользователя - экспортирует сессию в `avito_session.json`. Демон резидентного браузера подхватывает файл (в том числе при изменении) и заливает куки во вкладку. Ничего перезапускать не надо.

### 2. Резидентный браузер

`ff_browser_daemon.js` (Node, `firefox.launchServer`, порт 9334, прокси `socks5://127.0.0.1:10808`, выход в Москве) держит Firefox с вкладкой поиска «сво по контракту» постоянно.

Зачем так: если поднимать новый Firefox на каждый прогон, Авито флагает IP и показывает капчу. Постоянно открытая вкладка этого не даёт.

- ws-эндпоинт пишется в файл `browser.ws`, пульс каждые 45 секунд в `browser.heartbeat`
- лёгкий скролл раз в ~5 минут, мягкий reload раз в ~20 минут (когда сбора нет)
- попапы «Хорошо/Понятно/Принять» закрываются сами
- контекст пересоздаётся раз в сутки около 04:30 МСК (гигиена памяти)
- если демон умер, ff_collect уходит в фолбэк: свой persistent-профиль `ff_profile/`

### 3. Прогон ff_collect.py (--mode search)

1. `flock .parser.lock`. Два прогона одновременно невозможны: второй молча выходит с rc=2.
2. Подключение к резидентному браузеру (heartbeat свежее 180 секунд). Поиск «сво по контракту», сортировка «По дате».
3. Обход строго по порядку. DOM у Авито виртуализированный: при прокрутке карточки перемонтируются не по порядку. Поэтому каждый круг собирает смонтированные карточки с их координатами, сортирует по Y и обрабатывает непросмотренные сверху вниз. После порции - прокрутка 700-1100 px.
4. Дедуп. Нормализованный заголовок уже встречался (в этом прогоне или в базе с номером)? Карточка пропускается целиком, без ховера. Это клон, статус `dup_title`. Круг без живых карточек - быстрая прокрутка крупным шагом.
5. Телефон без захода в объявление. Hover по карточке, кнопка «Показать телефон», клик. Номер приходит картинкой (OCR tesseract, md5-кэш: у клонов одного рекрутёра картинка байт-в-байт одинаковая) или текстом. Нормализация `+7XXXXXXXXXX`. Нет кнопки телефона - статус `no_phone`, в следующие прогоны карточка не тыкается.
6. БД пишется по ходу. Каждый номер сразу после находки. Клоны и без-телефона пачками по 25. Авария или «Остановить» ничего не теряют.
7. Блоки. «Доступ ограничен» снимается нажатиями «Продолжить» и F5. Капча не решается: жёсткий cooldown 20 минут. SIGTERM - мягкая остановка, доканчивает карточку и сохраняет всё.
8. Повторы пропускаются. `done_ids` хранит все просмотренные id (с телефоном, no_phone, dup_title, error) и молча их скипает. Регулярные прогоны короткие, добирают только новое.

### 4. Отчёт excel_report.py

В отчёт идут только строки с телефоном. Колонки: Название, Телефон, Ссылка, Источник, Одинаковых вакансий, Описание (широкая, текст сниппета карточки). «Одинаковых вакансий» - сколько в базе объявлений с тем же текстом (клоны-спам одного рекрутера).

Каждый день на отдельном листе («19.09», «18.09» и так далее), свежий сверху. В 12:00 МСК бот присылает файл в чат. Если не получилось - ретраи каждую минуту до 12:59, максимум 10 попыток.

## Расписание (МСК)

| время | что происходит |
|---|---|
| 07:00, 08:00, 09:00, 10:00, 11:00 | тихий плановый сбор: поиск «сво по контракту», макс 300 номеров, бюджет 40 минут |
| 12:00 | эксель-отчёт в чат |
| ~04:30 | демон пересоздаёт контекст браузера |

Перед каждым плановым прогоном бот проверяет свободную память. При нехватке (около 2 ГБ) прибирает посторонний браузер; его сторож пересоздаёт сам. Каждую минуту cron `oom-priority` расставляет `oom_score_adj`: процессы сбора -200, посторонний Firefox +500.

## Управление

Кнопки бота: 📊 эксель, 🔍 спарсить «сво по контракту» (полный прогон и эксель), ⏹ остановить.

Команды: `/поиск /search`, `/стоп /stop`, `/эксель /excel`, `/start`. Чужие чаты молча игнорируются (`ALLOWED_CHATS`).

С сервера по SSH:

```bash
python3 /root/avito-svo/api_helper.py status        # сбор идёт? база? лог?
python3 /root/avito-svo/api_helper.py collect       # запуск: поиск, макс 300
python3 /root/avito-svo/api_helper.py collect search 100
python3 /root/avito-svo/api_helper.py stop          # мягкая остановка
python3 /root/avito-svo/api_helper.py report        # эксель -> base64
```

systemd и журналы:

```bash
systemctl status avito-svo-bot avito-svo-browser avito-ff-monitor
journalctl -u avito-svo-bot -f           # лог бота
tail -f /root/avito-svo/ff_collect.log   # живой лог коллектора
tail -f /root/avito-svo/browser_daemon.log
```

| файл | роль |
|---|---|
| `ff_browser_daemon.js` | резидентный браузер (вкладка Авито всегда открыта) |

## Зависимости сервера

Python 3.12, playwright (Firefox), tesseract-ocr с русским языком, openpyxl, requests. Для демона нужен Node-пакет драйвера playwright: `/usr/local/lib/python3.12/dist-packages/playwright/driver/package`.

Прокси `socks5://127.0.0.1:10808` (выход в Москве). X-дисплей `:1`, noVNC на 6080. TZ Europe/Moscow.

## Настройка (переменные окружения)

| переменная | по умолчанию | действие |
|---|---|---|
| `AVITO_ALLOWED_CHATS` | id владельца | кому бот раздаёт базу |
| `AVITO_MAX_PHONES` | 5 (юнит: 20) | лимит телефонов из карточек за сессию |
| `AVITO_COMPANY_COL` | выкл | `1` = добавить колонку «Вакансий компании» |
| `AVITO_PROXY` | `socks5://127.0.0.1:10808` | прокси браузера |
| `AVITO_BASE_DIR` | `/root/avito-svo` | базовый каталог |

## Запуск сбора вручную

```bash
DISPLAY=:1 AVITO_PROXY=socks5://127.0.0.1:10808 \
    python3 /root/avito-svo/ff_collect.py \
    --mode search --max-phones 0 --time-budget 1500
```

Аргументы: `--mode search|category` (search основной), `--query` (текст запроса), `--max-phones` (0 = без лимита), `--max-cards`, `--max-pages` (0 = вся пагинация), `--time-budget` (секунды).
